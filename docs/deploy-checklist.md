# Чек-лист после загрузки на хостинг

Бэкенд отзывов: `api/reviews.php` + `api/lib.php`. Админка: `admin/index.php` (папку можно переименовать).
Требования: PHP 7.4+ с mbstring, права на запись в папку данных.

## 1. Папка данных

По умолчанию данные лежат в `<сайт>/data/` в файлах `*.json.php`. Даже при прямом запросе такой файл
выполняется как PHP и отдаёт пустой 404, плюс папку закрывает `data/.htaccess`.

Надёжнее вынести данные за пределы сайта: создайте папку `vtd-data` **рядом с папкой сайта**
(на Reg.ru обычно `/var/www/uXXXXXXX/data/www/vtd-data`, если сайт лежит в
`/var/www/uXXXXXXX/data/www/vovrenyuk.ru`) с правами на запись. Бэкенд найдёт её сам.
Другой путь можно задать константой `VTD_DATA_DIR` в `api/config.php` (образец: `api/config.example.php`).

## 2. Пароль админки

Откройте `https://vovrenyuk.ru/admin/` **сразу после загрузки** и задайте пароль. Пока пароль не задан,
форму установки видит любой, кто знает адрес. Альтернатива: положить хеш в `api/config.php`
(`VTD_ADMIN_PASSWORD_HASH`), тогда форма установки не показывается вовсе.

## 3. Проверка защиты (вкладка «Диагностика» в админке показывает то же самое)

```
curl -sI https://vovrenyuk.ru/data/.htaccess            # ожидается 403 или 404
curl -sI https://vovrenyuk.ru/data/reviews.json.php     # ожидается 404 с пустым телом
curl -s  https://vovrenyuk.ru/api/config.example.php    # ожидается пустой ответ; если виден код PHP, PHP не выполняется
curl -sI https://vovrenyuk.ru/index.html | grep -iE "content-security|x-content-type|server"
curl -sI https://vovrenyuk.ru/assets/css/style.css | grep -i "^server"
```

Как понять, кто отдаёт статику: если в ответе на `style.css` заголовок `Server: nginx`, а в админке
«Веб-сервер» показывает Apache, значит nginx отдаёт статику напрямую, минуя `.htaccess`. Тогда:

- `data/` защищена всё равно (файлы `*.json.php` уходят в PHP, а лучше вынести папку, см. п. 1);
- CSP для главной страницы продублирован мета-тегом в `index.html`, он работает без сервера;
- остальные заголовки (`X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, HSTS)
  добавьте в настройки nginx через панель хостинга, значения возьмите из корневого `.htaccess`.

## 4. Чат Jivo и CSP

Jivo вставляет свой код inline-скриптом, поэтому в CSP стоит nonce. Страница статическая, значит nonce
постоянный: он прописан в трёх местах (`index.html`: мета-тег CSP и два тега `<script>`, плюс корневой
`.htaccess`). Меняя его, меняйте везде. После деплоя откройте сайт, дождитесь кнопки чата и загляните в консоль
браузера (F12): сообщений со словами «Content Security Policy» быть не должно.

## 5. IP посетителей

В админке на вкладке «Диагностика» строка «Определённый IP» должна совпадать с вашим реальным адресом.
Если там `127.0.0.1` или адрес сервера, впишите адрес прокси в `VTD_TRUSTED_PROXIES` в `api/config.php`,
иначе лимит «один отзыв в сутки» станет общим для всех посетителей.

## 6. Переезд с работающего сайта: порядок

1. Скачайте резервную копию текущей папки сайта целиком.
2. В панели хостинга проверьте версию PHP: нужна 7.4 или новее (лучше 8.1+), с расширением mbstring.
3. Залейте новые файлы. Нужны: `index.html`, `.htaccess`, `robots.txt`, `sitemap.xml`, `favicon.ico`,
   `apple-touch-icon.png`, папки `assets/`, `images/`, `api/`, `admin/`, `data/.htaccess`, `models/model.glb`.
   Не нужны на сервере: `.git/`, `viewer/`, `tools/`, `docs/`, `models/model.stl`, `models/model_raw.glb`.
4. Старые файлы сайта, которых нет в новой версии (например, `assets/js/three-scene.js`, `images/hero/engineer.jpg`),
   можно удалить: на них больше ничего не ссылается.
5. `data/reviews.json` с сервера оставьте на месте (или положите заново), `data/rate_limit.json` удалите:
   в новой версии другой формат и другой секрет, старые записи бесполезны.
6. Откройте `/admin/`, задайте пароль. Этот первый запрос импортирует старые отзывы: во вкладке
   «Опубликованные» должны появиться все записи из `data/reviews.json`.
   Если вкладка пустая, а файл на месте: удалите `data/reviews.json.php` (или тот же файл в `vtd-data/`) и обновите
   страницу, импорт запустится снова. Он срабатывает только пока нового хранилища ещё нет.
7. Пройдите проверки из пунктов 3 и 4 выше, откройте сайт с телефона и с компьютера: 3D-модель, чат, отзывы.
8. После успешного импорта `data/reviews.json` можно удалить или унести в резервную копию.

## 7. Импорт старых отзывов

Старый `data/reviews.json` (обычный JSON, как его писала прошлая версия) импортируется автоматически при первом
запросе к API или админке, если нового хранилища `reviews.json.php` ещё нет. Все записи попадают в «Опубликованные»,
id и даты сохраняются. После импорта старый файл можно удалить, вместе с `data/rate_limit.json`, если он остался.

## 8. Картинки, кэш, SEO

- Фото портфолио: положите новый `NN.jpg` в `images/projects/` и выполните `python3 tools/gallery.py NN.jpg`,
  затем добавьте ячейку в галерею по образцу соседних (варианты 480/800/1200 WebP, 800 и 1600 JPEG).
- Фото в блоке «О себе»: `python3 tools/photo.py путь/к/фото.jpg`.
- Превью для мессенджеров `images/og-cover.jpg` (1200×630) собирается из `tools/og-template.html`:
  откройте его через локальный сервер из корня сайта в окне 1200×630 и сохраните скриншот.
- Кэш (`.htaccess`): HTML не кэшируется, CSS и JS обновляются в течение часа, картинки 30 дней,
  модель 7 дней, шрифты год. Если заменили картинку или модель под тем же именем и нужно сразу,
  переименуйте файл или добавьте `?v=2` к ссылке в `index.html`.
- `sitemap.xml`: при заметных изменениях обновите `lastmod`. `robots.txt` закрывает `/admin/`, `/api/`, `/data/`.
